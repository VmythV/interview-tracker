# 面试追踪

记录自己作为面试者的投递与面试进度。React + TypeScript + Vite，**数据只存在浏览器的 localStorage 里**，不上传、不联网、没有后端。

## 跑起来

```bash
npm install
npm run dev        # 开发，热更新
npm run build      # 产出 dist/index.html（单个文件，直接双击就能用）
npm run preview    # 本地预览构建产物
npm run typecheck  # 只做类型检查
```

`npm run build` 用 `vite-plugin-singlefile` 把 JS/CSS 全部内联进一个
`dist/index.html`。这不是为了好看：外链的 `<script type="module">` 在 `file://`
下会被 CORS 拦掉，内联的不发请求，所以单文件产物可以直接双击打开，不用起服务器。
想放到任何静态托管上也行，`base` 已经是相对路径。

## 目录

```
src/
  types.ts               数据模型 + 流程常量（状态、图标、配色槽位）
  lib/
    date.ts              日期工具，一律走本地时区
    derive.ts            全部派生计算：筛选、排序、待办、KPI、漏斗、趋势、渠道
    storage.ts           localStorage 读写 + 外部数据的 normalize
    sample.ts            示例数据
    id.ts
  store/
    reducer.ts           所有状态变更收在这里，纯函数
    StoreContext.tsx     Provider + 持久化 + 写入失败上报
    ToastContext.tsx     toast（含撤销）
  hooks/
    useTheme.ts          深浅色，默认跟随系统
    useHotkeys.ts        全局快捷键
    useElementWidth.ts   ResizeObserver 量宽度
    calendar.ts          日历派生：事件摊平、周/月网格、重叠事件分列
  components/
    TopBar / FocusBoard / KpiRow / FilterBar
    BoardView / ApplicationCard / ListView / StatsView / EmptyState / StatusPill
    calendar/            CalendarView, WeekGrid, MonthGrid, EventChip
    charts/              ChartCard, StatusChart, FunnelChart, TrendChart,
                         SourceTable, TooltipContext
    drawer/              ApplicationDrawer, RoundTimeline, RoundEditor, Field
  index.css              设计令牌 + 全部样式

```

实体类型叫 `Application`（一次投递），没叫 `Record` —— 后者是 TS 内置工具类型。

## 记录了什么

每家公司一条：公司、岗位、城市、办公方式、渠道来源、薪资、投递日期、标签、备注、是否重点关注。

每条下面挂**多轮面试**：轮次名（一面 / 二面 / HR 面 …）、时间、形式（现场 / 视频 / 电话）、地点或会议链接、面试官、结果（待定 / 通过 / 未通过）、面试记录。

## 状态流转

```
想投 ○ → 已投递 ↗ → 笔试/测评 ✎ → 面试中 ◐ → 终面/待结果 ◆ → 已拿 Offer ★
                                                              ↘ 已结束 ✕
```

两种推进方式：**看板上把卡片拖到下一列**，或在详情抽屉里点「→ 下一步」。
每次流转都写进 `history`，抽屉里能看到最近四条。

- 状态是「已结束」时会追问原因（未通过 / 我拒绝了 / 无回应 / 主动放弃）——
  漏斗里才分得清「被刷掉」和「自己不去」。
- 记了面试轮次但状态还停在投递/笔试阶段，会自动推进到「面试中」。
- 每条记录另有 `reached`：**曾经**到过哪些阶段。漏斗统计用它而不是当前状态，
  所以一家被刷掉的公司仍然计入它走到过的最深一层。

## 录入一场未来的面试

打开那条投递 → 面试轮次里点「＋ 添加一轮」→「时间」直接选未来的日期和钟点（`datetime-local`，
精确到分钟）→「结果」保持「待定」→ 保存这一轮。

存好之后它会自动：进顶部待办区（今明两天标红、7 天内标黄）、显示在看板卡片上
（「三面（主管）· 明天 15:00」）、出现在日历里；排序选「最近面试」就按开始时间排。

时间可以留空 —— 面试约了但还没定具体时间时就这么记。这类轮次不落在日历的任何一天上，
会集中列在日历底部的「还没定时间的轮次」里。

## 日历视图

看板回答「走到哪一步了」，日历回答「某天几点要面试」。顶部可切**周 / 月**，
`‹ 今天 ›` 翻页。

- **周视图**是时间轴网格：纵轴是小时，事件按开始时间落位。默认显示 8:00–22:00，
  但一定会撑开到包住当周所有事件（早上 7 点的面试不会被裁掉）。今天那一列有底色，
  还有一条红色的当前时间线；打开时自动滚到「现在」附近。
  同一时段撞车的面试会**并排**放，不互相盖住。
- **月视图**每格最多显示 3 场，多了折成「还有 N 场」。点日期数字跳到那天的周视图 ——
  月视图看不出钟点，周视图能。

事件用**结果**着色并各带图标：待定 ◐（蓝）、通过 ✓（绿）、未通过 ✕（红）。
点任意一场直接打开对应投递的详情。悬停有完整信息（形式、地点、面试官）。

日历只画**已经定了时间**的轮次，并且和其它视图一样受上方筛选行约束 ——
所以「时间」筛的是*投递日期*，选了「近 7 天」时，更早投递的公司的面试也会一并被筛掉。

## 突出重点

页面顶部是待办区，只在有内容时出现，按紧急程度排：

1. 今明两天有面试（红）
2. 未来 7 天的面试（黄）
3. 超过 10 天没有进展的在投公司，建议跟进（灰）

点任意一条直接进详情。看板卡片上的下一场面试用同一套颜色标。

## 统计

- **各状态的公司数** —— 此刻停在哪一步
- **流程漏斗** —— 已投递 → 进入面试 → 走到终面 → 拿到 Offer，逐层给转化率和流失数（各层严格包含下一层）
- **每周投递量** —— 最近 12 周，带十字准星
- **各渠道效果** —— 投递 / 进面试 / Offer / 进面率

每个图表右上角可切**表格视图**，图上每个数字都能不靠悬停读到。
所有图表受上方同一行筛选约束，数字之间永远自洽。

## 快捷键

| 键 | 作用 |
|---|---|
| `N` | 新建投递 |
| `/` | 聚焦搜索框 |
| `Esc` | 关闭抽屉 |

抽屉打开时 `N` 和 `/` 会让路，不会在编辑途中又弹出一条新记录。

## 数据

改动即时写入 localStorage，没有「保存」按钮。

- **导出** —— 下载 JSON，文件名带日期
- **导入** —— 可选择替换或按 id 合并；任何外部数据都过一遍 `normalize`，字段缺失或类型不对会被补成合法值，不会把界面搞崩
- **删除** —— 有 7 秒撤销，多次删除各自撤销互不干扰
- **写入失败** —— 隐私模式或配额满时，页面顶部会出现红色告警提示先导出，不会静默丢数据

旧版（`records` 字段）的导出文件也能直接导入。

## 配色说明

图表配色跑过 `validate_palette.js`：

- 流程阶段是**单一蓝色 ordinal 阶梯**，浅色 250→550、深色 500→150，两种模式下
  「单一色相 / 明度单调 / 步距 ≥ .06 / 浅端对比度」四项全部 PASS
- Offer 用 good 绿 `#0ca30c`、已结束用 critical 红 `#d03b3b` —— 这两个颜色在红绿色盲下
  ΔE 只有 4.1，几乎不可分辨。**所以七个状态各配了一个不同形状的图标**
  （`○ ↗ ✎ ◐ ◆ ★ ✕`），卡片、看板列头、状态标签、图表、表格里都是图标 + 文字，
  颜色任何时候都不单独承载含义
- 文字一律用文本色，不穿数据色；身份由旁边的色块承载
- 深色模式是独立选色，不是把浅色反相

深浅色跟随系统，也可以用右上角按钮手动切换。
